2026년 8월 12일에 정보처리기사 필기를 봤고 가채점으로 합격했습니다. 마지막 이틀 동안 334문제를 풀었는데, 문제는 AI랑 같이 만든 문제은행에서 나왔어요.

어떻게 공부했는지 나중에 실기 준비할 때 다시 보려고 정리해 둡니다.

## 처음 계획

7월 말에 퇴사를 앞두고 정처기랑 SQLD를 같이 따기로 했습니다. 시험일은 8월 12일이었고, 처음엔 남들처럼 기본서를 사서 앞에서부터 읽었어요.

8월 3일에 확인해 보니 400쪽 중 100쪽을 읽은 상태였고 시험까지 9일이 남아 있었습니다. 그날 46쪽 읽는 데 1시간이 걸렸으니 이 속도면 이론만 읽다가 시험장에 들어가게 생겼더라고요. 그래서 책은 덮고 문제를 풀면서 틀린 걸 외우는 쪽으로 바꿨습니다.

## 1차 시도, AI 강의형

원래 쓰던 개인 학습 위키([LLM 위키](/posts/llm-wiki/))에 정처기 커리큘럼부터 만들었습니다. 책 목차를 그대로 체크박스로 깔고, Claude가 개념을 하나씩 설명하고 확인 문제를 내서 통과하면 위키에 개념 노트로 저장하는 방식이었어요.

```
한 줄 정의 → 쉽게 이해하기 → 핵심 정리 → 자주 나오는 함정 → 기출 포인트 → 확인 질문(4지선다)
```

결과적으로 커리큘럼 83개 항목 중 3개만 체크했고 개념 노트는 9개에서 멈췄습니다. 설명은 이해가 잘 되는데 속도는 책 읽는 거랑 비슷했어요. 생각해 보면 AI가 책을 대신 읽어 주는 것뿐이었으니 당연한 결과였던 것 같습니다.

## 2차 시도, 문제은행과 덤프 모드

시험 전날인 8월 11일에는 개념 공부를 아예 접었습니다. 문제를 먼저 풀고, 틀린 문제만 개념을 찾아보는 식으로요.

### 1. 문제은행 602문항

전날 밤 첫 덤프에서 틀린 유형과 최근 출제 경향을 반영해서 과목별로 JSON 문제은행을 만들었습니다. 과목당 120문항 정도이고 함정 보기를 섞어 넣었어요.

```json
{
  "id": "P4-001",
  "subject": "P4",
  "topic": "C 연산자",
  "q": "int a = 5, b = 2; printf(\"%d\", a / b); 출력 결과는?",
  "choices": ["3", "0", "2.5", "2"],
  "answer": 4,
  "why": "int/int는 정수 나눗셈, 소수부 절삭(반올림 아님)"
}
```

AI가 만든 문제를 그대로 믿기는 좀 불안해서 스크립트를 몇 개 붙였습니다.

- `validate.py`: 스키마, 중복 id, 정답 분포 검사
- `balance.py`: 선택지를 섞어서 정답 번호가 ①~④에 25%씩 가도록 배분 (정답 위치로 찍어서 맞히는 걸 막으려고)
- `dupcheck.py`: 거의 같은 문제 걸러내기
- `pick.py`: 이미 낸 문제(`asked.json`)는 빼고 5과목을 돌아가며 1문제씩 출제

그래도 풀다 보니 결함 있는 문제가 나오긴 했어요. C 포인터 문제 하나가 정의되지 않은 동작(UB)이라 정답이 없었고, 그 문제는 미채점으로 빼고 다시 냈습니다.

### 2. 한 번에 한 문제

제일 많이 손본 건 AI가 문제 내는 방식이었습니다. 처음에는 문제를 내고 해설에 변형 문제까지 붙인 다음 그 답까지 적어 버리더라고요. 혼자 내고 혼자 푸는 셈이죠. 제가 답하지도 않은 문제를 채점하고 넘어간 적도 있었고요.

그래서 이런 규칙을 넣었습니다.

```
1. 한 번에 문제 1개만. 문제 → 내 답 → 채점·해설 → 다음 문제.
2. 내가 선택지 번호로 답하지 않으면(되묻기·이의제기) 채점하지 않는다. 답해 주고 같은 문제를 다시 묻는다.
3. 해설은 그 문제 하나만. 변형 케이스는 다음 문제로 출제한다.
4. 새 문제는 메시지 맨 마지막에 두고, 그 뒤엔 아무것도 쓰지 않는다.
```

개인적으로 4번 효과를 제일 크게 봤어요. 문제 뒤에 "답을 기다릴게요" 같은 한 줄만 붙어도 AI가 제 답까지 이어서 써 버리는 일이 생겼는데, 문제를 메시지 맨 끝에 두고 바로 끝내게 하니까 없어졌습니다.

### 3. 답 기록과 세션별 보고서

푼 문제는 전부 표로 남겼습니다. 과목, 세부 개념, 정답, 제 답, O/X에 "찍음"이나 "본인 취약 신고" 같은 메모까지요.

```
| 24 | P4 | 서브네팅 호스트 수 계산(-2 규칙) | 2 | 3 | X (★크리티컬) |
```

세션이 끝나면 AI한테 로그를 읽고 취약점 보고서를 쓰게 했습니다. 과목별 점수, 반복해서 틀린 개념 순위, 오답 유형(계산형인지, 비슷한 개념이랑 헷갈린 건지, 그냥 안 외운 건지), 남은 시간에 뭘 할지가 들어갔어요.

## 정답률 기록

| 구간 | 문항 | 정답률 | 메모 |
|---|---|---|---|
| Q1~110 | 110 | 약 65% | P4(언어·OS·네트워크) 20%대, 과락권 |
| Q111~217 | 107 | 61% | P4 38% → 57%, 과락 탈출 |
| Q256~334 | 76 | 63% | 문항당 약 37초 |

평균 60%, 과목별 40%가 합격선이라 끝까지 턱걸이였습니다. 그래도 어디가 비어 있는지는 숫자로 바로 보여서 좋았어요. 책으로 공부할 때는 이게 안 보였거든요.

스케줄링 선점/비선점은 누적 다섯 번을 틀렸습니다. 보고서에 "선점 4개(RR, SRT, 다단계 큐, 다단계 피드백 큐)만 외우고 나머지는 전부 비선점"이라고 정리돼 있었는데, 그걸 보고 Q266에서 겨우 맞혔어요. 가용성(CIA)도 다섯 번 틀리고 Q267에서 맞혔는데 사용성이랑 계속 헷갈렸습니다. 서브네팅은 보고서에 "사실상 미학습 상태"라고 적혀 있었어요(맞는 말이라 할 말이 없었습니다).

P2가 86%에서 60%로 떨어진 세션도 있었는데, 보고서를 보니 암기형은 맞히는데 정렬 복잡도나 후위 표기, 해싱 같은 계산·변환형을 틀리고 있었습니다.

시험 직전 1시간 계획도 보고서가 짜 줬습니다. 남은 409문제 중 오답 기반 167문제에서 서브네팅, 정규화·정렬, OSI, 헷갈리는 개념 랜덤 순으로 15분씩 풀라는 내용이었어요. 그리고 그날 12시 40분 시험을 보고 가채점으로 합격을 확인했습니다.

## 개인적인 후기

제일 도움이 된 건 정답률 숫자였습니다. 막연히 P4가 약한 것 같다고 느끼던 게 "P4 38%"로 찍혀 나오니까 남은 시간을 어디에 쓸지 고민할 필요가 없었어요. 같은 개념을 몇 번째 틀리는지 세다 보니 네 번째쯤엔 외워지기도 했고, 이미 낸 문제를 다시 안 보니까 "이거 본 건데" 하고 맞히는 일도 없었습니다.

아쉬운 점도 있었습니다. 문제은행을 AI가 만들어서 실제 기출이랑 결이 다를 수 있고, 검증 스크립트는 형식만 보지 내용이 맞는지까진 못 봐요. 결함 있는 문제는 풀면서 직접 걸러야 했습니다. 솔직히 이해했다기보다 맞히는 법을 익힌 부분도 꽤 있는 것 같아요.

객관식 4지선다라서 이 방식이 통한 것 같기도 합니다. 지금 준비하고 있는 실기는 필답형이라 철자 하나까지 채점해서 그대로 쓰긴 어렵고, 코드 추적표를 직접 그리게 하는 쪽으로 바꿔 보는 중이에요.

다시 한다면 강의형은 건너뛰고 문제은행부터 만들 것 같습니다. 시작도 시험 전날 말고 2주 전쯤으로요. 문항당 37초면 100문제에 1시간이니까 하루 1시간씩만 해도 충분했을 것 같아요.

실기 붙으면 후기 또 올리겠습니다. 틀린 부분 있으면 댓글 달아주세요!
