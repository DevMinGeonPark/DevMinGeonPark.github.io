> 2026년 8월 12일 정보처리기사 필기 합격. 마지막 이틀 동안 책 대신 AI와 직접 만든 문제은행으로 334문제를 풀었다.

## 처음 계획

7월 말, 퇴사를 앞두고 정처기와 SQLD를 같이 따기로 했다. 시험일은 8월 12일이었고, 계획은 다들 하는 대로 기본서를 사서 앞에서부터 읽는 거였다.

8월 3일 기준으로 400쪽 중 100쪽을 읽었고 시험까지 9일 남았다. 46쪽 읽는 데 한 시간이 걸렸으니 계산해 보면 이론만 끝내는 데 시험 직전까지 다 쓰고 문제 풀 시간은 없다.

그래서 읽는 건 접고 문제부터 풀면서 틀린 걸 외우기로 했다.

## 1차 시도, AI 강의형(실패)

원래 쓰던 개인 학습 위키([LLM 위키](/posts/llm-wiki/))에 정처기 커리큘럼을 만들었다. 책 목차 그대로 체크박스를 깔고 Claude가 개념을 하나씩 강의하고 → 확인 문제를 내고 → 통과하면 위키에 개념 노트로 저장하는 구조였다.

```
한 줄 정의 → 쉽게 이해하기 → 핵심 정리 → 자주 나오는 함정 → 기출 포인트 → 확인 질문(4지선다)
```

커리큘럼 83개 항목 중 체크된 건 3개였고 개념 노트도 9개에서 멈췄다. 강의형은 이해는 잘 되는데 느리다. 책을 AI가 대신 읽어 주는 것뿐이라 속도 문제는 그대로였다.

## 2차 시도, 문제은행 + 덤프 모드

시험 전날(8/11)에 구조를 뒤집었다. 개념을 먼저 보고 문제를 푸는 대신 **문제 → 오답 → 개념** 순서로 갔다.

### 1. 문제은행 602문항

전날 밤 첫 덤프에서 나온 취약점과 최근 출제 경향을 반영해서 과목별 JSON 문제은행을 만들었다. 과목당 약 120문항이고 함정 보기를 섞었다.

```json
{
  "id": "P4-001",
  "subject": "P4",
  "topic": "C 연산자",
  "q": "int a = 5, b = 2; printf(\"%d\", a / b); 출력 결과는?",
  "choices": ["3", "0", "2.5", "2"],
  "answer": 4,
  "why": "int/int는 정수 나눗셈, 소수부 절삭(반올림 아님)"
}
```

AI가 만든 문제는 그대로 믿으면 안 돼서 스크립트 몇 개를 붙였다.

- `validate.py`: 스키마, 중복 id, 정답 분포 검사
- `balance.py`: 선택지를 섞어서 정답 번호를 ①~④에 25%씩 고르게 배분. 정답 위치로 찍어 맞히는 일을 막으려고.
- `dupcheck.py`: 거의 같은 문제 걸러내기
- `pick.py`: 이미 낸 문제(`asked.json`)는 빼고 5과목을 돌아가며 1문제씩 출제

실제로 풀다가 문제 결함도 나왔다. C 포인터 문제 하나가 정의되지 않은 동작(UB)이라 정답이 없었고, 그건 미채점으로 처리하고 다시 냈다.

### 2. 한 번에 한 문제

덤프 모드에서 제일 많이 손본 건 AI의 출제 습관이었다. 처음엔 AI가 문제를 내고 해설에 변형 문제까지 붙이고 그 답까지 써 버렸다. 혼자 문제 내고 혼자 푸는 거다. 내가 답하지도 않은 문제를 채점하고 넘어간 적도 있다.

그래서 규칙을 박았다.

```
1. 한 번에 문제 1개만. 문제 → 내 답 → 채점·해설 → 다음 문제.
2. 내가 선택지 번호로 답하지 않으면(되묻기·이의제기) 채점하지 않는다. 답해 주고 같은 문제를 다시 묻는다.
3. 해설은 그 문제 하나만. 변형 케이스는 다음 문제로 출제한다.
4. 새 문제는 메시지 맨 마지막에 두고, 그 뒤엔 아무것도 쓰지 않는다.
```

4번이 의외로 중요했다. 문제 뒤에 "답을 기다릴게요" 같은 한 줄이 붙으면 AI가 내 답까지 이어서 써 버리는 일이 생겼다. 문제를 메시지 맨 끝에 두고 바로 끝내게 하니 사라졌다.

### 3. 모든 답 기록과 세션별 보고서

푼 문제는 전부 표로 로그를 남겼다. 과목, 세부 개념, 정답, 내 답, O/X, 그리고 "찍음"이나 "본인 취약 신고" 같은 메모까지.

```
| 24 | P4 | 서브네팅 호스트 수 계산(-2 규칙) | 2 | 3 | X (★크리티컬) |
```

세션이 끝나면 AI가 로그를 읽고 취약점 보고서를 썼다. 과목별 점수, 반복 오답 순위, 오답 유형(계산형 / 유사 개념 혼동 / 단순 암기 누락), 그리고 남은 시간에 뭘 할지.

## 이틀간 정답률 기록

| 구간 | 문항 | 정답률 | 메모 |
|---|---|---|---|
| Q1~110 | 110 | 약 65% | P4(언어·OS·네트워크) 20%대, 과락권 |
| Q111~217 | 107 | 61% | P4 38% → 57%, 과락 탈출 |
| Q256~334 | 76 | 63% | 문항당 약 37초 |

평균 60%, 과목별 40%가 합격선이니까 계속 턱걸이였다. 그래도 어디가 구멍인지는 숫자로 보였는데, 책으로 공부할 때와 제일 다른 점이 그거였다.

- 스케줄링 선점/비선점: 누적 다섯 번 틀림. 보고서가 "선점 4개(RR, SRT, 다단계 큐, 다단계 피드백 큐)만 외우고 나머지는 전부 비선점"이라고 정리해 줬고, Q266에서 드디어 맞혔다.
- 가용성(CIA): 역시 다섯 번 틀리고 Q267에서 극복. 사용성과 계속 헷갈렸다.
- 서브네팅: 보고서 표현 그대로 "사실상 미학습 상태". 마지막 옥텟 대응표(128/192/224/240/248/252)만 외우라는 처방이 나왔다.
- P2가 86%에서 60%로 떨어진 세션은 보고서가 원인을 짚었다. 암기형은 되는데 계산·변환형(정렬 복잡도, 후위 표기, 해싱)이 안 된다는 것.

시험 직전 마지막 한 시간도 보고서가 짜 줬다. 남은 문제 409개 중 오답 기반 167개에서 상위 취약군만 15분씩, 서브네팅 → 정규화·정렬 → OSI → 혼동 개념 랜덤 순서였다. 가채점으로는 합격했다.

## 해 보고 느낀 점

### 효과 있던 것

- 정답률 숫자. 막연히 "약한 것 같다"고 느끼는 대신 "P4 38%"라고 나오니까 시간을 어디에 쓸지 고민할 필요가 없었다.
- 반복 오답 추적. 같은 개념을 몇 번째 틀리는지 세니까 네 번째쯤엔 진짜로 외워졌다.
- 출제 이력 관리. 같은 문제를 다시 안 보니 "이거 본 건데" 하는 착각 점수가 없다.

### 한계

문제은행이 AI 생성이라 실제 기출과 결이 다를 수 있다. 검증 스크립트는 형식만 보지 내용이 맞는지는 못 봐서 결함 문제는 풀면서 걸러야 했다.

이 방식은 필기라서 통했다. 객관식 4지선다는 "틀리고 외우기"가 잘 먹힌다. 지금 준비 중인 실기는 필답형이라 철자 하나까지 채점하기 때문에 같은 방식을 그대로 쓰긴 어렵다. 실기용으로는 코드 추적표를 직접 그리게 하는 쪽으로 바꾸는 중이다. 이해했다기보다 맞히는 법을 배운 부분도 분명 있다.

### 다시 한다면

처음부터 강의형을 건너뛰고 문제은행부터 만들겠다. 시작도 시험 전날 말고 2주 전으로 잡겠다. 하루 37초 × 100문제면 한 시간이다.
